# 卷 17 · Hooks 系统（生命周期钩子）

> Hooks 让用户与组织在**不改内核代码**的前提下干预 Agent 行为：在生命周期关键点插入校验、改写、通知与自动化。本卷定义**钩子点目录、钩子形态、语义（阻断/改写）、作用域与优先级、执行环境、超时与失败策略、调试与治理**。
>
> 需求来源：REQ-HOOK-1…8（卷 00 §5.17）；竞品参照：REQ-CMP-8（Claude Code Hooks 可阻断/改写）。

---

## 1. 本卷定位

- **解决**：在哪些点可以干预、干预能做什么、多个干预如何排序、失败怎么办、如何安全与可调试。
- **不解决**：权限决策本身（卷 06，钩子只能收窄不能放宽）、插件装载（卷 18）、事件流（卷 16，钩子执行结果作为事件记录）。
- **边界**：Hooks 是**用户/组织级的轻量策略与自动化**；复杂能力应实现为插件（卷 18）。

## 2. 需求与冲突点

| 需求 | 冲突/要点 |
| --- | --- |
| REQ-HOOK-3 阻断与改写 | 改写能力强大但风险高（可能破坏语义）→ 需声明式能力边界与校验 |
| REQ-HOOK-4 作用域 | 多层钩子冲突 → 明确优先级与合并规则 |
| REQ-HOOK-5 执行环境 | 钩子本身可能是任意脚本 → 必须在沙箱内执行并经权限治理 |
| REQ-HOOK-6 失败策略 | fail-open（流程继续）vs fail-closed（阻断）→ 安全默认 closed |
| REQ-HOOK-8 生态 | 钩子模板/市场需治理，避免「一键植入风险」 |

## 3. 设计空间（M×N）

### D-HOOK-1 钩子点粒度

| 分支 | 描述 | 结论 |
| --- | --- | --- |
| B1 少量（会话开始/工具调用前后） | 简单；覆盖不足 | 基线 |
| **B2 全生命周期目录（8 类 30+ 点）：会话、轮次、阶段、模型调用、工具调用、权限、审批、上下文、事件、计划/任务、提交/Git、插件/沙箱、系统** | 覆盖真实需求；点命名稳定并版本化 | **选定**（F=9 U=8 S=8 M=9 → 85.5） |

### D-HOOK-2 钩子形态

| 分支 | 描述 | 结论 |
| --- | --- | --- |
| B1 仅进程内插件 | 强；门槛高 | 基线 |
| **B2 四形态：① 声明式规则（YAML，覆盖常见校验/通知）② 脚本（Shell/Python/Node，经沙箱）③ 插件回调（进程内，性能好）④ HTTP 钩子（转发到企业服务）** | 覆盖不同技术栈与治理需求 | **选定**（F=9 U=8 S=8 M=9 → 85.5） |

### D-HOOK-3 干预语义

| 分支 | 描述 | 结论 |
| --- | --- | --- |
| B1 仅观察（通知/日志） | 安全；能力弱 | 基线 |
| **B2 三级能力：① 观察（记录/通知）② 阻断（拒绝继续，附理由）③ 改写（修改参数/结果/提示词片段，需声明可改写字段白名单）** | 覆盖真实需求；改写受限 | **选定**（F=9 U=8 S=8 M=9 → 85.5） |

**硬约束**：钩子**不能放宽权限**（不能把 DENY 改为 ALLOW）；改写仅限白名单字段（如工具参数中的路径、命令、提示词片段、结果摘要）；改写必须记录 diff。

### D-HOOK-4 作用域与优先级

| 分支 | 描述 | 结论 |
| --- | --- | --- |
| B1 单层（仅用户） | 简单 | 基线 |
| **B2 四层：组织 → 项目 → 用户 → 会话；求值顺序：组织（先）→ … → 会话（后）；安全类钩子（组织）不可被下级禁用；阻断即终止（后续不执行）** | 与卷 04/06 的层级一致 | **选定**（F=9 U=7 S=8 M=9 → 83.5） |

### D-HOOK-5 执行环境

| 分支 | 描述 | 结论 |
| --- | --- | --- |
| B1 内核内直接执行 | 危险（任意代码在核心进程） | 淘汰 |
| **B2 沙箱内执行（卷 07）+ 权限校验（卷 06）+ 资源限制（超时/内存/输出上限）+ 环境清洗（仅注入声明的变量与密钥引用）** | 安全 | **选定**（F=9 U=8 S=9 M=9 → 88） |

### D-HOOK-6 失败策略

| 分支 | 描述 | 结论 |
| --- | --- | --- |
| B1 一律 fail-open | 钩子失效时不阻断；安全类钩子失效＝风险 | 淘汰 |
| B2 一律 fail-closed | 安全；但一个坏钩子可瘫痪全部操作 | 淘汰 |
| **B3 按类型：安全/合规类默认 fail-closed；体验/通知类默认 fail-open；每钩子可显式声明；失败均记录并告警；连续失败自动禁用（熔断）并通知** | 平衡 | **选定**（F=9 U=8 S=9 M=9 → 88） |

### D-HOOK-7 超时与性能

| 分支 | 描述 | 结论 |
| --- | --- | --- |
| B1 无超时 | 钩子可挂死流程 | 淘汰 |
| **B2 每钩子超时（默认 2s，可配）+ 总预算（单次调用所有钩子合计 ≤ 5s）+ 异步钩子（观察类可异步，不阻塞）** | 体验可控 | **选定**（F=8 U=9 S=8 M=8 → 82.5） |

### D-HOOK-8 调试与治理

| 分支 | 描述 | 结论 |
| --- | --- | --- |
| B1 无 | 排障困难 | 淘汰 |
| **B2 调试能力：本地试跑（给定样例输入）、dry-run（只观察不改写）、执行日志与 diff、影响面统计（触发了多少次/阻断了什么）、一键禁用** | 可维护 | **选定**（F=8 U=9 S=8 M=9 → 84） |

### D-HOOK-9 分发与模板

| 分支 | 描述 | 结论 |
| --- | --- | --- |
| B1 用户手写 | 门槛高 | 基线 |
| **B2 模板库（格式化、敏感信息扫描、提交信息规范、通知集成、审计上报）+ 组织内分发 + 签名校验（企业可强制）** | 生态 | **选定**（F=8 U=8 S=7 M=8 → 77.5） |

## 4. 选定方案详设

### 4.1 钩子点目录（8 类 30+ 点）

| 类 | 钩子点 | 典型用途 |
| --- | --- | --- |
| 会话 | `session.create.before/after`、`session.close.before` | 初始化环境、清理 |
| 轮次 | `turn.start.before`、`turn.complete.after`、`turn.abort.after` | 注入上下文、通知 |
| 阶段 | `phase.plan.before/after`、`phase.execute.before`、`phase.verify.before/after` | 计划校验、验收强制 |
| 模型 | `model.request.before/after`、`model.error.after` | 请求改写（谨慎）、成本告警 |
| 工具 | `tool.call.before/after`、`tool.result.before/after`、`tool.error.after` | 参数校验、结果脱敏、格式规范 |
| 权限/审批 | `permission.decision.before/after`、`approval.request.before`、`approval.resolved.after` | 策略补充收窄、通知 |
| 上下文 | `context.assemble.before/after`、`context.compact.before/after` | 注入规范、压缩校验 |
| 计划/任务 | `workitem.create.before`、`workitem.state.changed.after`、`plan.update.before` | 模板校验、同步外部系统 |
| 提交/Git | `git.commit.before/after`、`git.push.before`、`pr.create.before/after` | 提交规范、扫描、通知 |
| 沙箱/插件/系统 | `sandbox.exec.before`、`plugin.load.after`、`system.ready.after` | 审计、自检 |

### 4.2 钩子定义（示例）

| 字段 | 说明 |
| --- | --- |
| `id` / `name` | 标识 |
| `point` | 钩子点（如上表） |
| `scope` | org / project / user / session |
| `match` | 匹配条件（工具名、路径模式、命令模式、事件类型、模型） |
| `capability` | observe / block / rewrite（rewrite 需附 `rewritableFields`） |
| `impl` | rule / script / plugin / http（含执行参数） |
| `failurePolicy` | fail-open / fail-closed |
| `timeoutMs` / `async` | 超时与是否异步 |
| `env` | 允许注入的环境变量与密钥引用（白名单） |
| `enabled` / `signature` | 开关与签名 |

### 4.3 执行管线中的位置

```mermaid
flowchart LR
  A["工具调用请求"] --> B["参数校验 卷05"]
  B --> C["Hooks 前置 tool.call.before 可阻断/改写"]
  C --> D["权限决策 卷06"]
  D --> E["Hooks 权限后 permission.decision.after 仅观察"]
  E --> F["沙箱执行 卷07"]
  F --> G["Hooks 结果 tool.result.before 可改写/脱敏"]
  G --> H["结果裁剪与回喂 卷05"]
  H --> I["Hooks 后置 tool.call.after 观察/通知"]
```

**顺序原则**：改写类钩子必须在权限决策**之前**（否则改写后未重新鉴权）；结果类钩子必须在脱敏**之后**（避免钩子看到明文敏感数据，除声明了敏感访问权限）；权限决策之后只允许**观察类**钩子。该顺序与卷 05 §4.2 执行管线逐步对齐，任一处调整必须同步修改另一处。

### 4.4 多层合并与冲突

| 场景 | 处理 |
| --- | --- |
| 多个阻断钩子 | 任一阻断即终止（按 组织→项目→用户→会话 顺序执行，先到先阻断） |
| 多个改写钩子 | 顺序应用；后一个看到前一个的结果；改写需通过 Schema 校验，否则拒绝该改写并记录 |
| 组织禁用某能力 | 下级不可启用（如「禁止用户钩子改写命令」） |
| 冲突检测 | 安装/保存时静态检测（同点同 match 的多个 rewrite 提示潜在冲突） |

### 4.5 安全模型

| 维度 | 要求 |
| --- | --- |
| 执行 | 沙箱内（卷 07），网络默认拒绝（除非声明域名） |
| 凭据 | 仅注入声明的密钥引用；日志脱敏 |
| 权限 | 钩子不能放宽权限；改写后必须重新走权限决策（若改写影响风险） |
| 数据 | 默认看不到敏感明文（除非声明 `sensitiveAccess` 并经授权） |
| 供应链 | 组织钩子签名校验；市场模板需审核与签名 |
| 熔断 | 连续失败 5 次自动禁用并告警（避免坏钩子拖垮流程） |

### 4.6 调试体验

| 能力 | 说明 |
| --- | --- |
| 本地试跑 | `oc hooks test <id> --input case.json`，输出判定、改写 diff、耗时 |
| dry-run | 只评估不生效（观察模式） |
| 影响面 | 统计触发次数、阻断率、改写次数、平均耗时 |
| 一键禁用 | 界面/CLI 禁用单个或全部钩子；禁用记录审计 |
| 回放 | 用历史事件重放钩子（验证新钩子对历史流程的影响） |

## 6. 事件与可观测

| 事件 | 说明 |
| --- | --- |
| `hook.executed` | 钩子执行（点、耗时、结果：pass/block/rewrite/crash） |
| `hook.blocked` | 阻断（含理由与后续影响） |
| `hook.rewritten` | 改写（含 diff 摘要与字段） |
| `hook.failed` / `hook.disabled` | 失败与熔断禁用 |
| `hook.installed` / `hook.removed` / `hook.updated` | 生命周期（含来源与签名状态） |

**指标**：`oc_hook_exec_total{hook,result}`、`oc_hook_latency_ms{hook}`、`oc_hook_block_total{hook}`、`oc_hook_rewrite_total{hook}`、`oc_hook_failure_total{hook}`、`oc_hook_disabled_total`。

## 7. 非功能设计

- **性能**：同步钩子总开销 ≤ 5s/次调用（默认 2s 单钩子超时）；异步观察类不阻塞；钩子数量上限（默认 50/作用域）。
- **可靠性**：钩子崩溃不影响主流程（按失败策略）；熔断后自动禁用并告警；配置持久化。
- **安全**：沙箱执行、最小权限、改写白名单、签名校验、失败默认 closed（安全类）。
- **可维护**：钩子配置可 diff、可评审；钩子执行全量审计；提供 `oc hooks` 诊断命令。
- **可移植**：钩子定义可随项目（`.oc/hooks/`）版本化，跨实例一致。

## 8. 完成定义（DoD）

- [ ] 30+ 钩子点落地并在文档中逐个标注语义与可用能力（observe/block/rewrite）。
- [ ] 四形态钩子（规则/脚本/插件/HTTP）全部可用，至少规则与脚本有端到端测试。
- [ ] 三级能力生效：改写仅限白名单字段；改写后重新走权限决策（用例）。
- [ ] 四层作用域与优先级规则实现；组织禁用不可被下级启用（用例）。
- [ ] 失败策略按类型生效：安全类 fail-closed、观察类 fail-open；熔断禁用可用。
- [ ] 超时与总预算生效（钩子挂死不影响主流程，用例）。
- [ ] 调试能力：本地试跑、dry-run、影响面统计、一键禁用全部可用。
- [ ] 安全：钩子无法放宽权限（用例）；无法读取未声明敏感字段（用例）。

## 10. 开放问题与默认决策

| 项 | 默认决策 |
| --- | --- |
| 默认是否启用任何钩子 | 默认零钩子（不干预）；模板可按需安装 |
| 钩子脚本语言 | 默认 Shell + Python + Node（探测环境）；其他语言经容器 |
| 钩子能否发起网络请求 | 默认不能；声明域名白名单后可（走网络策略与审计） |
| 钩子与 Skill 的关系 | Skill 可携带推荐钩子（安装时提示），但不自动启用 |
| 钩子市场的审核 | 默认「扫描 + 签名」；企业私仓可要求人工审核 |
