# Phase B 实现层总索引（`docs/harness/impl/`）

> 本目录是 OpenCoding Harness 目标态设计的**实现落地层**：35 份 `NN-*-impl.md` 逐系统回答「怎么做（how）」，并把每个技术分叉冻结为 `I-<域>-<n>` 实现级决策，全部汇总于本目录 `IMPL-DECISIONS.md`。
> 上游输入：`docs/harness/` 根目录 36 卷（Phase A 目标态设计，what/why）+ `DECISIONS.md`（H-/D- 决策台账）+ `research/`（9 家竞品源码级研究 + `CROSS-COMPARISON.md` + `LESSONS-AND-ADOPTIONS.md` 采纳台账）。

## 1. 本目录定位

### 1.1 Phase B 与 Phase A 的关系

| 维度 | Phase A（`docs/harness/` 根目录） | Phase B（本目录 `impl/`） |
| --- | --- | --- |
| 回答的问题 | 做什么、为什么（what / why） | 怎么做（how）——技术方案、类契约、数据模型、时序、DoD |
| 产出形态 | 36 卷设计 + `DECISIONS.md`（H-xxx / D-<域>-n）+ `ALTERNATIVES.md` + 附录 A–D | 35 份 `NN-*-impl.md` + `IMPL-DECISIONS.md`（`I-<域>-<n>`）+ 本 README |
| 决策编号 | `H-xxx` 全局、`D-<域>-<n>` 域内 | `I-<域>-<n>` 实现级，**只增不复用**，不覆盖 D- |
| 冲突处理 | 冻结契约，不因 Phase B 修改 | 冲突/缺口一律登记为**修订建议 X-n**（`IMPL-DECISIONS.md` §4），不回改 Phase A 卷册 |
| 证据来源 | 产品愿景 + 决策日志 | Phase A 卷 + 竞品源码级证据（`[E1]`–`[E4]`，见 `research/00-research-plan.md` §2） |

写作前必读：`research/00-research-plan.md` §3（写作模板）与 `LESSONS-AND-ADOPTIONS.md` §6.2（登记规则 G1–G8）；涉及 Java 形态的代码示例必须符合 `.qoder/rules/` 五条规范（注释 / 配置抽取 / 常量抽取 / 异常处理 / 日志）。

### 1.2 写作模板摘要（11 节固定顺序）

| 节 | 内容 | 硬性要求 |
| --- | --- | --- |
| ① 实现目标与范围 | 对应 Phase A 卷号与决策号；解决什么 / 不解决什么；上下游依赖 | 标注「依赖修订 X」 |
| ② 功能需求清单 | `REQ-<域>-n`：需求描述 + 来源（卷章节 / 竞品证据等级）+ P0/P1/P2 + 验收要点 | ≥2 条来自竞品研究的增量需求 |
| ③ 技术方案选型 | ≥3 个维度 M×N 比选（每维度 ≥2 分支）+ 评分矩阵（F30/U20/S25/M25）+ 选定分支 + 被放弃分支代价 + 回退触发 | 每选定分支登记 `I-<域>-n`，≥3 条/文件 |
| ④ 总体架构图 | Mermaid `flowchart`：模块/类族/依赖方向，标注内核 or 外壳、Spring 装配点 | 图数量入本 README §2 |
| ⑤ 类图 | Mermaid `classDiagram` + 关键 Java 21 签名（接口/构造/泛型） | 签名不得出现魔法值与裸异常 |
| ⑥ 核心流程时序图 | Mermaid `sequenceDiagram` ≥3 个；每个配前置条件 / 主路径 / 异常补偿 / 幂等并发点 | — |
| ⑦ 状态机 | Mermaid `stateDiagram-v2`（有状态实体时） | — |
| ⑧ 数据模型 | `oc_*` 表（字段/索引/约束/分区）+ Redis Key（统一 Key 工厂）+ 对象存储前缀 + 事件清单 | 新增表登记为修订建议或附录 A 增补 |
| ⑨ 接口与扩展点 | REST/WS 端点（+错误码）、SPI（对接卷 18 目录）、配置项（`open-coding.*` + 环境变量 + 默认值 + 必填性）、**错误矩阵（场景 → 错误码 → 对外文案 → 处置）** | 敏感项留在环境变量 |
| ⑩ 非功能与工程细节 | 并发模型、性能预算（数字）、容量估算、缓存、失败降级、安全（**含安全边界检查清单**）、可观测（指标/日志/span） | 含 Phase A 差异与修订建议小节 |
| ⑪ 测试与验收（DoD） | 单测/集成/契约/回放用例、故障注入、性能门禁、可执行验收命令（`mvn -pl … test`） | 每条断言可机械执行 |

写作硬约束：全中文正文（专有名词保留英文）；Mermaid 必须合法（`flowchart`/`classDiagram`/`sequenceDiagram`/`stateDiagram-v2`）；禁止 TODO/占位符；每条关键设计能指回 Phase A 卷/决策号或登记 `I-`。交付实际体量 800–1000 行/文件（模板目标 500–900 行，本目录含附录整体略高）。

### 1.3 阅读顺序建议（按依赖 01 → 35）

- **速读入口**：只读每份的 §1–§3（范围 → REQ → 比选结论与回退），30–60 分钟可掌握一个系统的全部实现决策。
- **默认顺序**：01 → 02 → … → 35（下文 §3 给出三条按依赖重排的路径）。
- **对照阅读**：读任一 `NN-*-impl.md` 时并行打开 `IMPL-DECISIONS.md` §2 对应域分组，可一键看到该文件的全部 `I-` 决策与回退条件。

## 5. 维护约定

### 5.1 新增一份实现方案（`36-*.md` 及以后）

1. **先对齐上游**：确认对应 Phase A 卷/决策号；若为新建卷（如本目录 31/32 对应的卷 34/35），先在 `DECISIONS.md` 追加 D- 条目与域编码，再动笔。
2. **按 11 节模板写作**（§1.2 摘要；全文见 `research/00-research-plan.md` §3），单文件 500–900 行（本目录实际 800–1000 行），≥5 张 Mermaid 图、≥3 个 `I-` 决策、≥2 条竞品增量 REQ。
3. **域编码分配**：沿用 `DECISIONS.md` §0 域编码表；Phase B 新增域须先在 `IMPL-DECISIONS.md` §1.2 注册（本批新增 COST/SEC/DIST/ECO/UX/AUTO/INTEL/OPS/DSK 共 9 个）。
4. **登记决策**：文件 §3 每选定分支登记 `I-<域>-<n>`（n 从该域已有最大值 +1，**不复用、不跳号语义**）；同时在 `IMPL-DECISIONS.md` §2 对应域分组追加一行（六列齐全）。
5. **冲突处理**：与 Phase A 不一致 → 只写建议，登记 `IMPL-DECISIONS.md` §4 汇总表（分配新的 X-n），并在文件 §1 标注「依赖修订 X-n」；**禁止**修改 Phase A 卷册。
6. **台账回引**：REQ 来源字段写 `research/LESSONS-AND-ADOPTIONS.md L-0xx`（含证据等级）；被采纳机制必须出现在 §3 比选中（G2）。
7. **同步本 README**：§2 索引表追加一行并更新合计；§3 若引入新依赖关系需同步路径表。

### 5.2 编号规则（强制）

- `I-<域>-<n>`：域编码见 `IMPL-DECISIONS.md` §1.2；一个域只对应一份 impl 文件；跨文件引用他域决策只引用不登记。
- `REQ-<域>-n`：延续 Phase A 卷 00 的需求编号体系；续号文件在 §2 标题显式声明断点（如 impl/24「续卷 00 §5.23 的 REQ-A2A-1…10」、impl/25「续 REQ-ENT-1…12」）。**对 Phase B 新建卷（34/35）例外**：impl/31 的 `REQ-AUTO-1…16` 为对卷 34 的**严格同义引用**（另 17/18 为本层新增）；impl/32 采用**独立局部号段** `REQ-INTEL-I<n>`，禁止写出与卷 35 同串不同义的 `REQ-INTEL-n`——引用卷 35 需求一律写全称「卷 35 REQ-INTEL-n」。
- `X-n`：修订建议编号，在本 README §4 与 `IMPL-DECISIONS.md` §4 双处同步；一经分配不复用。
- **一致性硬约束**：任何 `REQ-` / `I-` 编号以 `IMPL-DECISIONS.md` 台账为准——文件与台账不一致时，以台账为唯一事实源回改文件；新增/删除编号必须在台账 §3 统计中同步反映。

### 5.5 异常命名约定（跨 35 份统一，R02 裁决）

全套 impl 文件统一三层异常体系，禁止第四套命名、禁止裸抛：① **内核层**（`harness-contract` / `core-*`，零 Spring）失败一律抛 `HarnessException(ErrorCode, 中文文案)` —— 携带统一 `ErrorCode` 与中文文案，例：`throw new HarnessException(ErrorCode.CONFLICT, "该租户已有恢复扫描在途，请稍后重试")`；② **外壳层**（`host-*` / `platform-*` / Spring 应用服务）失败抛出 `BusinessException(ErrorCode, 中文文案)`（与 `.qoder/rules/exception-handling-rules.md` 的项目统一业务异常对齐）；域内专用异常（如 `SandboxException`、`HookException`）必须**继承**二者之一，不得平行造根；③ **模型/适配层**（四协议 SDK 边界）必须翻译为 `AiException(ErrorCode)`（D33），SDK 原始异常不得外溢；④ **全局异常处理器按 `ErrorCode` 映射**为附录 B §B.7 统一错误响应，业务代码不得 try-catch 后自行包装返回；⑤ 系统级不可恢复场景（配置缺失/验签器不可用）允许原始 `RuntimeException` 子类携带 cause，但**禁止**用 `RuntimeException` / `IllegalArgumentException` / `NullPointerException` 表达业务失败，**禁止**空文案异常。各文件 §⑨ 错误码小节末条已注明本文件所属层带对应的异常类名。
