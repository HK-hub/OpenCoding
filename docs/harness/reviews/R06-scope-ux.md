## 一、方法与可复核口径

1. 对每个客户端追问四件事：**首屏定义（可验收）/ 每一步的时长目标 / 每一步失败时的恢复动作 / 跳过与中断后的续接**——四者缺一即记为缺口。
2. 交互状态按「界面族 × 六态」逐格核对：矩阵里有、平台实现里没有（或反之）都算缺口；每格必须同时有**呈现**与**恢复动作**（「请重试」不算动作）。
3. 审批与中断以 `impl/06` §3.7.8 为**唯一权威**逐条对表：超时动作、终态封闭集、级联拒绝、预览 `action_digest`、去重窗口、六级记忆范围。
4. 开发回路只认「可复制执行的命令 + 时长预期 + 测试选择指引 + 零凭证」四要件；无时长的命令视为不可验收。
5. 文案只认「键空间 + 中文基线 + 三段式 + CI 判据」；示例文案违规即就地改写（含 31/32/33 错误矩阵）。

| 端 | 首屏定义 | 步骤链 | 时长目标（P95） | 失败恢复 | 原稿状态 → 本轮处置 |

## 七、文案与本地化

1. **键空间**（新增 `30` §9.6，唯一权威）：`ui.<surface>.<element>.<variant>`；`surface` 取 11 个界面族 code + `ui.common.*` + `ui.firstrun.*`；禁止序号式临时键。
2. **中文基线**：`zh-CN` 为源语言与基线；缺键回退基线并计数（不显示键名、不空白）；企业术语只叠加不删除。
3. **三段式**：错误文案强制「**事实 + 原因 + 动作**」，同条内可读；新增 CI 第 4 条扫描——**错误类文案缺动作段即失败**（`lint:copy`，`30` §9.6 / `22` REQ-CLI-18 / `23` §10.7 同一规则）。
4. **违规样本已改**：`22`「未响应，已按安全默认处理」→「审批超时（<timeout>s 内未响应），已按策略拒绝；可重新发起或调整审批策略」；`30` §9.5 全表重写；`31` §9.4 全表重写（含「接管通道不可用」由 `BLOCKED` 更正为 `ESCALATED`，与 §6.4 对齐）；`32` §9.5 全表重写（能力禁用改为「置灰 + 原因」而非「隐藏入口」）；`33` §9.5 全表重写。
5. **变量契约**：每条文案声明占位符类型与溢出策略；缺失走保护性占位并计数。
