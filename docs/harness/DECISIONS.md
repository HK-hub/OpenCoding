## 1. 全局决策（H-xxx）

### H-001 产品本体：Harness 平台化

| 项 | 内容 |
| --- | --- |
| 分叉维度 | ① 单体编码助手 ② 编码助手 + 可编程 SDK ③ **Harness 平台**（内核 + 端 + 生态三层） |
| 候选分支 | B1 单体助手：把 Agent 能力做进一个应用，功能闭环但不外露内核<br>B2 助手 + SDK：应用为主，另发 SDK，但内核与 UI 耦合<br>B3 Harness 平台：内核（Kernel）与所有界面物理解耦，端与生态都是内核的消费者 |
| 选定 | **B3 Harness 平台** |
| 理由 | F：功能全景（35 域 386 项能力）只有平台化才能承载；S：内核无 UI/框架依赖 → 单测与多端复用成本最低；M：扩展与市场是长期护城河；U：CLI/TUI/桌面/IDE/headless 同源体验一致。B1/B2 在 F、M 上显著落后 |
| 影响面 | 全卷；尤其卷 01（内核/外壳分离）、18（扩展）、22（多端）、23（被调用） |
| 回退触发 | 若平台化导致单机 CLI 冷启动 > 300ms 或内存 > 200MB（卷 22 指标），启用轻量内核裁剪档（H-004 的 local-lite 形态） |

> 口径注（R03 跨语料轮）：本条「内存 > 200MB」的**卷 22 出处经核验不成立**——卷 22 §7 的指标为桌面端空闲内存 ≤ 350MB（NFR-P-7，卷 00 §6.1 同）；CLI/TUI 侧内存门禁在 Phase B 落为 `impl/22` §10.2「3 会话 TUI 常驻 RSS ≤ 120MB」。300ms 冷启动与卷 22 / NFR-P-6 / `impl/22` §10.2 一致。后续统一口径建议：回退线引用「NFR-P-6 + `impl/22` §10.2 内存门禁」，不改动本条既有数字与 `ALTERNATIVES.md` 回退列。

### H-002 运行拓扑：常驻内核 + 多前端

| 项 | 内容 |
| --- | --- |
| 分叉维度 | ① 进程内嵌 ② 每次调用起进程 ③ **常驻内核 + 多前端接入** |
| 候选分支 | B1 单进程内嵌（UI 与内核同进程）<br>B2 无状态子进程（每次调用起停）<br>B3 常驻内核进程（Daemon/Kernel），CLI、桌面端、IDE、远程客户端通过本地 IPC + HTTP/WS 接入；内核可被托管为服务器实例 |
| 选定 | **B3，且内核必须支持「单机内嵌」启动档**（CLI 短会话可内嵌内核、长会话自动升级为常驻） |
| 理由 | F：多端同源、被其他 Agent 调用（卷 23）、后台 Schedule/Teams 都要求常驻；U：会话热态复用、秒级恢复；S：进程隔离让前端崩溃不影响 Agent 运行；B2 冷启动与状态丢失不可接受 |
| 影响面 | 卷 01、22、23、24；会话协议卷 B |
| 回退触发 | 若 IPC 协议成为性能瓶颈（P95 增量延迟 > 50ms），退化到进程内直连通道 + 共享内存传输 |

### H-003 内核形态与依赖边界

| 项 | 内容 |
| --- | --- |
| 分叉维度 | ① 全 Spring Boot 单体 ② 纯 Java 内核 + Spring 外壳 ③ 内核用非 JVM 语言 |
| 候选分支 | B1 全 Spring：开发一致，但内核强绑定容器与 Web 生态，单测与嵌入困难<br>B2 纯 Java 内核（无 Spring/无存储依赖，端口-适配器）+ Spring Boot 外壳（应用服务、存储适配、REST/WS）<br>B3 内核用 Rust/TS（性能好、生态近）但栈分裂、企业 Java 团队维护成本高 |
| 选定 | **B2**（Java 21 内核 + Spring Boot 3.x 外壳，技术栈要求不变） |
| 理由 | S：内核可纯 JVM 单测、可嵌入 CLI、可被 headless 服务复用；M：边界清晰，Spring 只出现在外壳，升级风险被隔离；F：内核 API 即为插件 SPI 的稳定面。B1 在 S/M 明显落后，B3 在 M 上不可接受 |
| 影响面 | 卷 01；所有卷的实现边界必须标注「内核 or 外壳」 |
| 回退触发 | 若内核接口膨胀到无法内聚（> 400 个公开类型），允许按子域拆为多个内核模块，但不得引入 Spring 依赖 |

### H-004 部署形态

| 项 | 内容 |
| --- | --- |
| 分叉维度 | ① 仅本地 ② 仅云 ③ **同源多形态**（local / local-lite / server / enterprise-server / air-gapped） |
| 候选分支 | B1 纯本地（隐私好，团队协作与后台任务弱）<br>B2 纯云（协作好，隐私与延迟差，企业私有化受阻）<br>B3 同源五形态：`local`（个人桌面+CLI）、`local-lite`（极简 CLI 短会话）、`server`（团队共享实例）、`enterprise-server`（多租户 + SSO + 审计）、`air-gapped`（离线内网，禁用外部模型路由） |
| 选定 | **B3** |
| 理由 | F：企业级要求私有化与团队协作并存；S：同一内核、不同装配，避免形态分叉维护；M：部署形态由配置与能力门控决定，不发散代码 |
| 影响面 | 卷 01、20、24；能力门控表（卷 00 §功能矩阵） |
| 回退触发 | 形态数量导致测试矩阵爆炸（> 5×3 组合）时，收敛为 local / server 两形态 + 特性开关 |

### H-005 状态存储分工

| 项 | 内容 |
| --- | --- |
| 分叉维度 | ① 纯文件 ② 纯关系库 ③ **PostgreSQL 事实源 + Redis 运行态 + 对象/文件仓库** |
| 候选分支 | B1 文件（SQLite/JSONL）简单但并发与多租户弱<br>B2 关系库单栈，热路径压力大<br>B3 PG（事件、会话、任务、记忆、知识元数据）+ Redis（会话热态、锁、队列、缓存、限流）+ 文件/对象存储（工作区快照、媒体、索引文件） |

| 影响面 | 卷 01、19、16、24 |
| 回退触发 | 若本地单机形态下 PG 运维成本被判定过高，启用「嵌入式后端」适配器（同一仓储接口的本地实现），应用层不变 |

| 候选分支 | B1 直接方法调用，无事件<br>B2 Spring 事件通知，进程内<br>B3 追加式事件日志（append-only，按会话/任务分区）+ 投影出读模型 + 实时订阅推送；支持回放与审计 |

### H-009 沙箱模型

| 项 | 内容 |
| --- | --- |
| 分叉维度 | ① 无隔离 ② 单一隔离实现 ③ **分级隔离（策略选择档位）** |
| 候选分支 | B1 直接执行<br>B2 仅容器<br>B3 分级：L0 受控本地（资源限制 + 路径围栏 + 环境清洗）→ L1 容器 → L2 微虚拟机（Kata/Firecracker 类）→ L3 远程执行节点；按风险与租户策略自动选档，失败可降级到更高隔离 |
