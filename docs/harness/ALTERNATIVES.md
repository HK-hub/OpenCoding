# 备选分支档案（Alternatives & Fallback Paths）

> 本文件是「M×N 平行多分支」的**显式交付物**：每个决策点的**被放弃分支**、放弃理由、以及**回退触发条件与切换代价**都在此登记。
>
> 目的：当现实条件变化（平台能力、规模、合规、成本、客户要求）时，团队可**按档案切换分支**，而不必重新论证整个架构。
>
> 约定：`选定分支` 见 `DECISIONS.md`；分支候选的完整描述与评分见各卷「设计空间（M×N）」节（本文件给出行号无关的章节定位）。

## 3. 分支切换的操作规程

```mermaid
flowchart LR
  A["触发条件出现（监控/评审/客户要求）"] --> B["在 DECISIONS.md 记录变更提案（含证据）"]
  B --> C["评估影响面（依赖该决策的卷与实现）"]
  C --> D{"影响面可控?"}
  D -->|是| E["按本档案的切换代价执行 + 回归评测"]
  D -->|否| F["升级为全局架构评审（多方案重新比选）"]
  E --> G["更新 DECISIONS.md 与相关卷册（先文档后代码）"]
  G --> H["跑门禁（卷 26 变更矩阵）+ 灰度验证"]
  H --> I["发布说明记录分支切换与理由"]
  F --> B
```

**规则**：
1. 切换分支必须**先改文档**（决策台账 + 受影响卷册），再改代码（README §7-1）。
2. 每个切换必须跑对应门禁；涉及安全/迁移的分支切换必须额外通过红队与迁移测试。
3. 分支切换记录进入发布说明（用户可感知的行为变化必须显式说明）。
4. 同一决策 12 个月内反复切换 ≥ 2 次，视为架构信号，触发全局评审（可能是上游需求未澄清）。
