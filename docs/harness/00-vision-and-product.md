## 3. 愿景与产品定位

**一句话**：OpenCoding 是**企业级多模态 Coding Agent Harness 平台**——内核（Kernel）可独立运行、可被任意前端与外部系统集成，向上提供 CLI 与桌面端两种一等体验，向外提供插件、Skill、MCP、A2A 四种扩展与互操作路径。

**三条产品承诺**：

1. **同源双端**：CLI 与桌面端共享同一内核、同一会话、同一权限与审计；在终端里开始的会话可以在桌面上继续，反之亦然。
2. **可扩展到底**：从模型、工具、技能、记忆后端、沙箱、工作区、审批策略到 UI 面板，全部可替换、可组合、可市场分发。
3. **企业级可用**：多租户、审计、配额、私有化部署、离线内网、数据可迁移，全部默认内建。

### 3.1 用户画像

| 角色 | 核心诉求 | 关键功能域 |
| --- | --- | --- |
| 个人开发者 | 低摩擦、强自主、终端与桌面协同 | 会话、工具、上下文、Skill、记忆 |
| 团队 Tech Lead | 并行任务、审查流、成本可控 | 任务/计划、Teams、Git/Worktree、计量 |
| 平台/基础设施工程师 | 私有模型、私有工具、策略与合规 | 模型接入、插件、权限策略、沙箱、审计 |
| 企业 IT / 安全 | 隔离、审计、数据驻留、SCIM | 多租户、SSO、沙箱、日志、数据治理 |
| 集成方（其他 Agent/平台） | 以 API 驱动 OpenCoding 或反向调用 | A2A、headless 服务面、事件流 |

### 3.2 核心场景（12 个）

1. 终端内的会话式编码：读代码 → 改代码 → 跑测试 → 提交，全程可中断、可回退。
2. 桌面端多面板协作：会话 + 计划 + 差异 + 团队视图同屏。
3. 大仓改造：跨模块重构，靠任务分解 + worktree 隔离 + 合并队列落地。
4. 无人值守自动化：定时依赖升级、PR 巡检、文档同步（Schedule）。
5. 长程目标：给定验收标准的「把 X 特性做完」，自主推进数小时并定期汇报（Goal）。
6. 多 Agent 团队：架构 Agent + 实现 Agent + 测试 Agent + 审查 Agent 并行协作。
7. 企业知识问答：基于代码库 + 内部文档的检索问答与引用溯源。
8. 私有模型接入：内网 vLLM/Ollama 模型，禁外网，全链路审计。
9. 远程开发：SSH 到构建机 / 容器工作区内执行。
10. 被集成：CI 流水线通过 headless API 提交任务并接收事件。
11. 设计到代码：设计稿/截图输入 → 前端实现 → 视觉对比迭代（多模态）。
12. 插件扩展：企业内部插件提供私有工具、审批策略与面板。

| 产品 | 强项 | 我们吸收 | 我们超越 |
| --- | --- | --- | --- |

### 4.3 结论：我们必须做对的 8 件事

1. **内核与端解耦**（否则多端与生态不可持续）。
2. **事件即事实源**（回放/审计/多端同步/恢复共用一条流）。
3. **权限-沙箱-审批三件套**做到企业级深度（这是多数开源 harness 的短板）。
4. **扩展点覆盖全生命周期**，且插件有权限边界与签名验证（DeepSeek 的密度 + Claude Code 的体验 + 我们自己的治理）。
5. **上下文工程**是第一等公民（压缩、检索、缓存亲和、可视化）。
6. **任务-计划-目标-调度统一模型**（避免四套对象模型互相打架）。
7. **多 Agent 编排可观测、可介入、可接管**（成本与信任决定可用性）。
8. **数据可迁移、可恢复、可审计**（企业采购的硬门槛）。

## 7. 产品层铁律（体验十条）

1. **永不静默失败**：任何降级、跳过、裁剪都必须显式告知并可追溯。
2. **永远可打断**：任何长流程在 ≤ 1s 内响应中断意图，并给出收尾状态。
3. **审批不打扰**：可批量、可记住、可时间窗；打扰次数与风险成正比。
4. **成本前置可见**：每个动作前可预估影响（token/时间/风险），事后有账单。
5. **状态可解释**：Agent 的每个决策（工具选择、权限请求、压缩）都能给出理由。
6. **双端等价**：CLI 能做到的，桌面端不缺失；桌面端能做到的，CLI 有等价命令。
7. **可复现**：任何会话可导出为可复现包（环境+事件+产物引用）。
8. **默认安全**：默认最小权限、默认沙箱、默认不外发。
9. **渐进自主**：自主度随信任提升（建议 → 协作 → 自治），且可随时收回。
10. **数据归用户**：全部数据可导出、可迁移、可删除，格式开放。
